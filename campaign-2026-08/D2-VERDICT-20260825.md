# D2 verdict: new-tree port, aeon shortcut DEAD — standing directive

Decision (Joe, 2026-08-25, source-verified same day): D2 proceeds as the days-class port
onto the new b12x tree. The aeon-lineage shortcut is closed. Sequenced BEHIND D6 (drafter
finetune) and D1 (TailQuant-uniform encode), which are already unblocked.

## The evidence chain (all checked against the actual trees, not release notes)

1. The on-disk aeon platform image (glm52-spark-platform:aeon-0.27.1) pins b12x at
   334a2d75 -- the production pin ask 1 proved has ZERO BTX machinery. Aeon as built
   carries nothing D1 needs.
2. No intermediate pin exists with both the old API and BTX: b12x's integration/mla died
   2026-07-20 (restructure commit 142662a57, same day as the b12x->sparkinfer rename);
   BTX arrived 2026-08-16 (btx_schema 5e3e9885d, end-to-end 930a83ee2). Empty overlap
   window. Rebuilding b3 at an intermediate pin cannot work.
3. The removed API was REPLACED, not abandoned: docs/mla_sm120_postmortem.md (in-tree at
   the 36bce2c15 pin) documents a ground-up CuTeDSL sparse-MLA backend at
   b12x/attention/mla/ with explicit GLM_NSA support (uncompressed, arbitrary-FP32
   inline scales -- our exact configuration), accuracy >=0.9995 vs a dense FP32 oracle,
   157 tests passing, and a claimed 1.2-1.6x speedup over the legacy kernels for GLM at
   batch=1 decode (their measurement, RTX PRO 6000 sm_120 -- until-reproduced here).
   Front-door functions (sparse_mla_decode_forward etc.) auto-route to it on SM120+.

## What the port now buys (why days-class is worth paying)

- BTX serving tier (the D1 container's only home; confirmed new-tree-only by ask 1).
- The new GLM_NSA sparse-MLA backend: the first credible single-stream decode kernel win
  on the table all campaign, IF the 1.2-1.6x reproduces at our shapes.
- The 222-commit upstream delta (route-packing fixes, PCIe DCP owner exchange,
  topology-scoped AR).

## Port scope

Rewrite the kit overlays' imports from the removed b12x.integration.mla surface onto the
new namespaced plan/bind/run API. The overlay->new-tree mapping table from ask 1 is the
work plan. Acceptance: parity boot passes the gate, then the standard one-shot battery +
GSM8K vs the noise floor. The 1.2-1.6x GLM_NSA claim gets verified in that same boot, not
taken on faith.

## Window 1 context this verdict rests on

A1 (b3 parity) FAILED deterministic: kit overlays import b12x.integration.mla, absent
from the 1.2.6 tree. That failure is what triggered this investigation; the gate did its
job, and the answer upgraded the port from "cost to reach BTX" to "cost to reach BTX
plus a candidate decode kernel win."
